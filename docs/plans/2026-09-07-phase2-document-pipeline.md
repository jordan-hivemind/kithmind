# Phase 2: document pipeline and recovery

**Date:** 2026-09-07

**Status:** Implementation sequence under P2-0. This plan does not claim that the worker, parser, or restore path already exists.

## Outcome

A configured document folder feeds the shared Brain without manual copy and paste. The worker notices changes, retains evidence, publishes validated records, and reports failures. Desktop clients answer from hosted records and text while the worker or original file is unavailable. Hosted read tools remain the mobile boundary; native client support stays a separate P2 priority.

Start with a small synthetic corpus, then a measured owner pilot. A verified isolated restore is required before ingesting any owner documents. Bulk backfill requires the recovery, quality, and capacity gates below. The public recipe must work with another person's own accounts and folders. Owner paths, account mappings, and real evaluation material stay outside git.

This plan implements the [architecture](2026-09-06-architecture.md), especially T1-T3, T7, and T17-T18. It retains the [reuse assessment](2026-09-06-reuse-assessment.md): evaluate Docling conversion before building OCR, keep Paperless optional, and adapt the pinned upstream exporter rather than create another generic export format. Those are scoped reuse decisions, not measured parser or recovery results.

## Remote worker and durable admission

Create a small TypeScript pipeline package with a versioned transport client, connector interface, local journal, and stage runner. Keep parser-specific Python code behind an adapter process. A cloud-source connector can use the same transport without depending on a Mac filesystem.

The first protocol exposes only the operations required by the worker. Reuse the gateway's verified credential-to-principal boundary and existing lease/stage helpers. The server derives the actor; request bodies cannot provide a trusted user or credential ID. Each operation checks the live key, membership, enabled source, and job/source parent chain. Original submitting credentials remain part of the audit. Recovery cannot silently replace a revoked actor with an administrator.

Use explicit destination and source-account IDs in worker configuration. Never depend on a person's changing default destination. Source configuration changes that alter root, destination, or connector identity require a new identity or an explicit migration. A stable watcher identity includes deployment, source account, connector version, and host affinity; affinity is routing metadata, not authorization or a lease.

Persist discovery and its canonical request envelope locally before sending it. Store the returned cloud receipt before acknowledging local progress. After an uncertain response, repeat the identical request ID, epoch, and payload. Read current desired epochs through the scoped protocol; resolve conflicts instead of inventing new IDs until an update succeeds. The local journal is restart state, not a second authoritative record database.

Add metadata-only discovery runs, bounded due-job reservation, and full-scan reconciliation to the remote protocol. Existing `advanceCursorAndEnqueue` accepts full inline admissions, and `claimJob` needs a known job ID; neither alone supplies a remote discovery queue. A completed scan must have a server-validated inventory of seen items and a committed end marker. Only that reconciliation may establish missing items.

Where the existing cloud cursor admission fits, reuse atomic discovery admission and cursor advancement. The current four-discovery transaction bound still applies. A connector may checkpoint only after every discovery in that checkpoint has a durable receipt. Compute coverage from the validated enumeration run and its processing inventory. Record-type/date coverage additionally requires versioned playbook classification of every in-scope discovered item and server-verified terminal outcomes for that type and interval. Unknown dates, unsupported or oversized documents, review candidates, parser failures, and skipped items remain explicit gaps or pending inventory. A complete folder scan alone cannot establish financial-record coverage. Do not accept arbitrary worker-supplied counts as proof of completeness. Enumeration completion and processing completion are separate states. A record awaiting parsing is pending work even when its folder scan completed.

Processing claims use the existing five-minute lease and fenced renewal/completion. Long parser calls renew before expiry. A stale process may retain local output but cannot stage or activate it under an old lease. Bound retries and backoff, surface exhausted jobs, and preserve the previous validated generation on replacement failure. Do not make embeddings a prerequisite for exact records and keyword evidence.

## Filesystem identity and safe reads

The first filesystem worker watches only explicitly configured roots. Record root aliases in public examples and keep absolute owner paths in local configuration. Resolve credentials through a host credential store or an explicitly supplied process environment; never put them in the source inventory, journal payload logs, or public fixtures.

Assign each discovered item a source-local UUID and persist its identity and path mapping in both the local journal and a paginated, source-scoped cloud identity manifest. The current capped `list_sources` response is not that recovery protocol; P2-7 must add it. Manifest list/read/reconcile operations require the live credential's exact source-account ingest grant and current space membership. They return only connector identity/path/reconciliation state, not retained document text, and do not require broad read capability. Separate equal-content files receive separate identities. Exact known path bindings can recover the current mapping, but a filename, content hash, or inode alone cannot establish a rename or merge two identities.

The default worker does not add sidecars or xattrs to original folders. If a rename coincides with journal loss and no independent mapping survives, unmatched files and old items enter explicit identity review. Do not assign replacements, mark the old items unavailable, or promise automatic recovery in that case. A reviewed remap preserves the source identity. Preserve minimal non-content tombstone/alias digests needed to block forgotten-path reimport after journal loss. Test the privacy and recovery behavior of that manifest before owner use.

Reject traversal outside the selected root. Do not follow symlinks by default. Check the opened file and its metadata so a changed path or file during reading causes retry instead of mixed bytes. Bound file size, parser time, memory, subprocess output, and the number of in-flight jobs. Defaults and overrides must be documented and fixture-tested. Oversized or unsupported items remain visible as skipped or review work; never truncate them and publish a complete document.

A missing mount, denied directory, cloud-only placeholder, failed read, or interrupted enumeration is a coverage gap. It is not evidence of source deletion. Mark an item unavailable only after a healthy completed reconciliation establishes its absence. Unavailability preserves retained evidence; explicit forget is a separate authorized operation. Forgotten identities must remain protected from automatic reimport, including after a local journal is rebuilt.

The first worker handles small UTF-8 text files. PDF, image, Office, and archive-service inputs begin only after their adapters and provenance contracts pass. Automatic URL fetching is separate work and must first add redirect, DNS/private-network, credential, size, and timeout defenses.

## Original bytes, parsing, and evidence

P2-9 must distinguish original source bytes from extracted text. Add an explicit source representation and immutable archive reference rather than reinterpret existing text hashes. Preserve the existing text-only revision and replay behavior. The first supported artifact path is a local encrypted archive with an independent encrypted backup. The authenticated worker hashes the complete original bytes and writes an immutable archive receipt containing the hash, byte length, media type, archive identity, and receipt version. Store the digest as `worker_asserted`, not `server_verified`, because the cloud service has not read those bytes. The isolated restore recomputes the plaintext hash and records that verification separately. A future uploaded-artifact path may use server-side hashing, but must not relabel earlier worker assertions as server verification.

Retain an independently restorable original artifact or document that it is unavailable. Specify where encryption occurs, where keys are kept, who can retrieve bytes, and how restore verifies plaintext hashes. A local path or expiring download URL alone is not an archival guarantee. The local encrypted archive recipe must pass independent backup and restoration before owner-document use. Hosted evidence remains readable without those bytes.

Store parser version/configuration, model assets, lossless conversion output, normalized text, page mapping, and locators. Conversion offsets must be translated into the Brain's page-relative UTF-16 convention with fixture checks for non-ASCII text and multi-page tables. A parser bounding box does not prove an exact quote offset. Every cited field must resolve to retained text or an explicitly modeled non-text locator; do not fabricate a text span for an unreadable field.

A parser update or manual correction creates a new processing/text version as needed while retaining the same original revision when bytes are unchanged. Rechunking uses retained text and does not require OCR again. Publication remains atomic across exact records, evidence, documents, and keyword chunks. Larger documents need a reviewed bounded storage and activation strategy; the current 32-page, 128-span, and 32-event generation limits are not a claim of full-statement support.

## Playbooks and quality decisions

Playbooks define accepted document classes, required fields, entity mapping, event and observation keys, exact value normalization, evidence requirements, and uncertainty behavior. Keep prompts, schemas, parser settings, and normalization versions in the processing fingerprint. Untrusted document instructions cannot change source access, tools, outbound destinations, or publication rules.

Add a versioned financial field catalog and durable review-candidate payloads; the current generic observation-type strings and money validator are not a complete playbook. Start financial work with statement fees and receipt line items. Use the existing `financial_transaction` and money types. Keep parser amounts as strings throughout normalization, using `canonicalizeDecimal`, `validateCurrencyCode`, and `addDecimals` from `models/records/values.ts`. Never convert through a JavaScript floating-point number before validation or aggregation. Preserve repeated equal amounts on distinct source lines, refunds/signs, currency, statement period, and unknown dates. A stable provider transaction ID is preferred when present. Otherwise use a documented source-local row identity and retain ambiguous matching for review; do not deduplicate by amount and date. Within a statement, distinguish summary totals from the constituent line items so a fee summary is not counted again as a transaction. Cross-source copies remain independent unless explicitly linked and the query policy makes that relationship clear.

T1 uses existing `sum_money` semantics with statement/source breakdown and coverage. Add bounded authorized document/source display metadata where the current response exposes only IDs, so a person can identify each statement without searching the originals. T2 identifies recorded tax fields and distinguishes recorded values from calculations. Unsupported tax quantities remain unavailable. Contract answers quote retained text. Synthetic lab and service fixtures exercise repeated observations, event dates, entity separation, and immutable evidence. Workout extraction is optional.

Review candidates are inert and excluded from active records and exact queries. Unresolved candidates block relevant record/date coverage. Candidate reads and resolution require current space roles; an ingest worker cannot approve its own ambiguity merely by resubmitting it. Resolution is single-use and idempotent, records the actor, and rejects stale or conflicting decisions. Accepting a correction creates and atomically activates a new immutable processing/text/record generation through the correction-revision mechanism. It never patches active observations or silently mutates parser output. Test cross-space access, stale generations, repeated resolution, and concurrent corrections before owner use.

Entity assignment uses configured source mappings or explicit reviewed matching. Do not infer that every lab belongs to the uploader or that an account belongs to a similarly named family member. Review uncertain identities and values before publishing them as validated records.

Parser support and an LLM confidence score are not accuracy measurements. Label the expected fields, missing values, citations, and query answers first. Record the task-specific pass thresholds before running the evaluation; changing a threshold afterward requires a stated reason and a new result. Authorization and citation-parent-chain failures are release blockers. Report exact-value accuracy, field coverage, citation correctness, duplicate/missed events, family isolation, retrieval recall, latency, total pages, and actual model/retry cost. Compare two or three chunking choices and relevant embedding candidates without changing the active model until a compatible replacement generation is ready.

## Monitoring, backup, and restore

Heartbeat status must live in the cloud so a dead host cannot conceal its own failure. Track last heartbeat, completed enumeration, completed processing, oldest pending work, failures, and known coverage gaps separately. A green HTTP endpoint or recent heartbeat alone does not prove source access or historical completeness.

Create deduplicated cloud incidents for missing worker, revoked credentials, inaccessible roots, stuck queues, failed parsing, and paused budgets. Dashboard/doctor visibility is required. Sending email or chat alerts is an optional configured delivery path that requires the owner's channel authorization; this plan does not authorize messages to others.

Adapt the exporter inspected at upstream commit `0534744fdb7f366d38e89e44c82f3da22ae4c958`, preserving attribution. Re-audit its completeness against today's tables. Export schema-versioned JSON plus evidence/archive manifests. Markdown may be useful for interchange but is not the recovery format. Use a consistent snapshot or verified high-water-mark protocol; a live unordered traversal cannot promise an internally consistent backup.

Exclude reusable secrets from ordinary exports. Restore credentials through a separate secure procedure. Preserve or explicitly remap all references, family membership, source identities, revisions, evidence, current pointers, and tombstones. Define durable records separately from ephemeral leases, query cursors, and OAuth grants. Add an explicit restore mode that disables workers and outbound processing in the restored target until mappings and permissions are verified. Do not restore API credentials as active in an isolated drill.

The final restore drill must use the same schema as the owner pilot, including durable discovery identities/receipts, watcher configuration, review candidates, field catalogs, source display metadata, and archive manifests. Earlier restore success is not sufficient after those tables are added. Compare counts and hashes, then check exact values, historical corrections, sampled citations, private/shared authorization, and forgotten-record behavior. Record measured recovery point and time; do not invent an availability guarantee. Document backup retention and when forgotten content expires from older backups. Failure of archive-byte recovery is reported separately from success of hosted-text recovery.
