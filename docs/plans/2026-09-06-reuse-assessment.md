# Kith Mind open-source reuse assessment

Date: 2026-09-07. Task: R2-1. Status: recommendation after a static GBrain feasibility spike.

## Recommendation

Retain the existing Convex application as the authoritative Brain. Validate **Docling** as the preferred document-conversion adapter against representative fixtures. Keep **Paperless-ngx** optional for households that want a separate document archive and its UI. Reuse **GBrain** selectively for protocol ideas, tests and export compatibility, but do not place a GBrain database plus a Kith-specific sidecar in the authoritative path.

GBrain overlaps substantially with the desired product. It has local and hosted MCP transports, hybrid retrieval, temporal facts, typed metric trajectories, source-scoped OAuth clients, connectors, health checks and exportable Markdown. The source spike found more structure than its high-level memory-verb documentation exposes. It also found that the remaining gaps fall at Kith Mind's core boundary: exact money, an event identity shared by its observations, field and revision evidence, deterministic domain aggregates, family membership and item-level sharing. A sidecar would have to implement those requirements, authorize them, synchronize them with GBrain and decide which store wins after corrections. That removes less custom work than adding the same records and queries to the existing Convex service, which already supplies the application, authentication, MCP gateway, lifecycle facts and retrieval.

The highest-payoff reuse is therefore:

1. Validate Docling conversion and locators on synthetic and consented statement and lab fixtures before selecting it.
2. Extend the current store with space, document revision, evidence, event and observation records. Keep exact domain queries in that service.
3. Preserve the upstream JSON export as the recovery and migration format. Keep its GBrain-shaped Markdown as a lossy interoperability export.
4. Implement or adapt GBrain's small memory-verb facade only if client portability proves useful. Do not make the frozen verbs the record schema.
5. Add Graphiti or Mem0 later only as rebuildable projections when a measured retrieval need justifies them.

This does not require another replacement gate before implementation. Native mobile remains priority P2 and can be tested against the hosted Brain after the desktop path works.

## GBrain feasibility spike

The spike inspected GBrain at commit [`ede85e2e8c510077e6505f1c30257dc64176361b`](https://github.com/garrytan/gbrain/tree/ede85e2e8c510077e6505f1c30257dc64176361b), dated 2026-09-06. It used an isolated shallow clone under `/tmp`, after inspecting repository instructions. No dependency install, server, account, hosted deployment or production data was used. Findings below are static contract findings, not runtime certification.

### What fits natively

- The `facts` table has validity windows, lifecycle links, confidence, source and source session. Its numeric `id` identifies a stored fact. Fence-backed facts also use a partial unique key on `(source_id, source_markdown_slug, row_num)`, so two rows on one entity page remain distinct when their row numbers are stable. See the [base fact DDL](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/migrate.ts#L2383-L2419) and [batch conflict key](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/pglite-engine/facts.ts#L210-L248).
- Typed metric facts add `claim_metric`, `claim_value`, `claim_unit` and `claim_period`. `find_trajectory` filters by entity, metric, source, date and visibility, then returns points in `(valid_from, id)` order. See the [typed migration](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/migrate.ts#L3388-L3412), [query](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/pglite-engine/facts.ts#L480-L576) and [MCP operation](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/ops/insights.ts#L249-L335).
- Event-shaped fact rows have a free-text `event_type`. The same trajectory read can filter them. GBrain's own type comment says richer event-shape filtering was still a future task at this commit. See [`TrajectoryOpts`](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/engine.ts#L660-L725).
- GBrain also has an ontology observation operation with source, confidence and valid dates. It treats a new value as a current-state supersession and an equal value as corroboration. That is useful for current attributes such as role or risk tolerance. See [`ontology_propose`](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/ops/chronicle.ts#L153-L187) and its [merge logic](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/postgres-engine.ts#L4010-L4071).
- OAuth clients can carry one source or a federated source list, and remote facts are limited to `world` visibility. This is meaningful tenant isolation for agent clients. See the [OAuth projection](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/src/core/oauth-provider.ts#L952-L974) and [memory protocol trust boundary](https://github.com/garrytan/gbrain/blob/ede85e2e8c510077e6505f1c30257dc64176361b/docs/protocol/MEMORY_VERBS_v1.md#L361-L365).

The equal-lab case therefore passes only as a numeric trajectory. The authoritative record case fails on compound identity, evidence and exact query semantics. GBrain plus a sidecar would still need Kith Mind's planned `spaces`, `documents`, `revisions`, `evidence`, `events`, `observations`, `coverage`, jobs and query services. It would also add dual-write or projection reconciliation. Keeping Convex avoids that second authority while allowing GBrain-compatible exports and verbs.

The upstream `ai-brain` exporter makes compatibility practical. At upstream commit [`0534744fdb7f366d38e89e44c82f3da22ae4c958`](https://github.com/flippyhead/ai-brain/tree/0534744fdb7f366d38e89e44c82f3da22ae4c958), [`scripts/export-brain.mjs`](https://github.com/flippyhead/ai-brain/blob/0534744fdb7f366d38e89e44c82f3da22ae4c958/scripts/export-brain.mjs) emits a faithful JSON archive and explicitly lossy GBrain-shaped Markdown. The Markdown maps fact lifecycle and source text into GBrain fences. It does not export Kith Mind's future events or field evidence, so JSON must remain authoritative. The upstream repository did not expose a root license through the GitHub license API during this review; the plugin manifest's MIT label does not settle the license scope of every inherited file.

## Component guidance

Docling covers the generic parsing work that should not be rebuilt casually. Its [supported formats](https://github.com/docling-project/docling/blob/main/docs/usage/supported_formats.md) include PDF, Office files, images, HTML, email and XBRL. `DoclingDocument` models hierarchy, tables, pictures and layout; each [`ProvenanceItem`](https://docling-project.github.io/docling/reference/docling_document/#docling_core.types.doc.base.ProvenanceItem) carries a page number, bounding box and character span. Preserve original hashes, converter version/configuration, lossless JSON and locators, then let versioned Kith Mind playbooks create observations. Format support alone does not establish field accuracy, so this remains an adapter to validate rather than an adoption decision. Docling Graph's richer provenance ledger can be evaluated separately after the converter passes.

Paperless-ngx is useful when the archive UI and workflows are desired products. Its [usage guide](https://github.com/paperless-ngx/paperless-ngx/blob/dev/docs/usage.md) covers mail rules and workflows; its [API](https://github.com/paperless-ngx/paperless-ngx/blob/dev/docs/api.md) exposes object permissions. If used, keep it a separately deployed service and store its document and page references in Kith Mind evidence. Avoid making it mandatory because it creates a second operational system without removing the domain model.

Graphiti and Mem0 can consume authoritative outputs later. Graphiti's [MCP server](https://help.getzep.com/graphiti/getting-started/mcp-server) can add and search temporal episodes, but an [open RFC](https://github.com/getzep/graphiti/issues/1379) documents missing built-in authentication and per-group authorization in the OSS HTTP surface. Mem0's [write path](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/how-it-works.mdx) extracts and deduplicates conversational facts, and its [search guidance](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/memory-operations/search.mdx) requires identity filters. Both are better treated as rebuildable indexes than source-of-truth records.

Khoj and Open Notebook remain useful product references. Khoj's [self-hosting](https://docs.khoj.dev/get-started/setup/) and [desktop client](https://docs.khoj.dev/clients/desktop/) show approachable onboarding and folder sync. Open Notebook demonstrates heterogeneous [source intake](https://github.com/lfnovo/open-notebook/blob/main/docs/3-USER-GUIDE/adding-sources.md) and clickable [citations](https://github.com/lfnovo/open-notebook/blob/main/docs/3-USER-GUIDE/citations.md). Those patterns can inform Kith Mind without adopting either application's storage boundary.

## Limits

This was a bounded primary-source review of seven projects plus a static, pinned-source GBrain feasibility check. It did not run third-party servers or test suites, inspect every transitive license, benchmark extraction or retrieval, audit security, validate hosted terms or test mobile clients. The GBrain conclusions apply to the inspected commit and public/internal contracts named above; later operations could change the fit. Docling still needs fixture-backed accuracy and locator tests before selection.
